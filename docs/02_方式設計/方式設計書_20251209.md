# 方式設計書

## 全体方式

- FastAPIでOrder Serviceを提供する。
- 注文はSQLiteに保存し、配送ステータスは保持しない。
- Controller層はHTTPリクエストとレスポンスを扱い、Service層のユースケースを呼び出す。
- Service層は注文取得にRepositoryを、配送ステータス取得に外部APIクライアントを利用する。
- Repository層はSQLite/SQLAlchemyとドメインモデルを変換する。外部API層は配送APIとのHTTP通信を担当する。
- 起動処理で依存関係を組み立てる。HTTPクライアントはアプリケーションの起動中に共有し、終了時にクローズする。
- Service層が注文を取得し、外部配送APIを注文単位で呼び出して結果を組み立てる。
- 外部配送システムAPIは外部ベンダーのAPIである。そのため外部結合テストまでは外部配送システムのモックを使用する。

ドメインモデルはWeb・DBフレームワークに依存させない。RepositoryはSQLAlchemyのレコードをドメインモデルへ変換し、DBの詳細がService層へ広がらないようにする。

## 外部API連携

配送ステータスは注文単位のHTTP要求で取得する。

外部配送システムAPIの詳細仕様は、[外部API仕様書（配送ステータス）](./外部API仕様書_配送ステータス_20251209.md)を参照する。
